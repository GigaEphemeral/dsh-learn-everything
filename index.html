Why · 问题

漂亮的笔记，然后呢？

看到好文章，收藏！看到好教程，收藏！收藏的时候感觉自己又进步了——但过了几天，嗯？好像又忘了。问题可能不在于笔记整理得不够漂亮，而在于知识存下来之后：

Q1
真正理解了吗？UNDERSTAND — 读过 ≠ 懂它的因果
Q2
能记住吗？REMEMBER — 没有复习调度，遗忘是必然
Q3
碰到问题能用出来吗？APPLY — 看懂一遍和自己讲清楚，是两回事
保存 ≠ 理解 ≠ 掌握

AI 时代，你本身的视野和知识储备，才能带你走得更远。这个项目想做的，就是把「存下来」变成「学进去」。

Core · 三大核心能力

摄入、检索、练习——一条命令的距离

所有操作都以 DSH 斜杠命令为唯一入口，右侧栏面板可视化知识图谱与学习状态。

CAPABILITY 01

安全摄入

/obs-remember-knowledge

把 URL 或本地资料丢进系统，它不会乱动你的库——自动查重、预检、两段确认，以 create-only 方式安全写入 Sources/，再由 KarpathyWiki 编译成 wiki/ 派生知识网。

  • 预检查重注册表 content_hash 精确查重 + 同 slug 相似查重，重复材料进不来
  • 只 create、绝不覆盖所有对正式 Vault 的写入都经过确认门禁，人工笔记永不被静默改动
  • 编译可追溯每个 wiki 派生页带 source_file，可回溯到摄入原文
DSH · 摄入与编译
预检 PASSED · 无重复 · create-only 写入 · 内容哈希读回校验通过
CAPABILITY 02

证据检索

/obs-knowledge-search

不是每次遇到问题都去海量资料里重新翻一遍，而是从自己积累的知识里找到相关内容和依据，带上可信引用。

  • Wiki 优先先查 KarpathyWiki 编译层，命中概念/实体节点，再回原始笔记取证
  • 意图分类 + 分词回退停用词剥离、元数据文件过滤，检索策略为知识网量身定制
  • 答案有出处每条结论附来源路径（如 wiki/concepts/json-schema.md），可点开验证
Obsidian · 知识图谱
摄入越多，图谱越密 —— 检索走的是你的知识，不是互联网的
CAPABILITY 03

每日一练 + 高压追问

/obs-daily-practice · /obs-grill-me

从 wiki 节点即时抽题、评估作答。如果你答「不会」，它不会直接给你答案，而是像严厉的老师一样逐步追问，直到你真的讲清楚——至少，不能总用「我好像懂了」骗自己。

  • 评分 < 6/10 强制追问触发 /obs-grill-me，每轮一个关键问题，压测目标/证据/因果/边界/反例，最多 8 轮
  • 掌握度持久化题目、作答、评分全部只追加存 SQLite；错题只写学习状态，绝不污染正式笔记
  • 智能复习排期间隔递增 + 加权选题（逾期/薄弱/覆盖/新颖），到点自动出现在练习里
DSH · 每日一练
深度追问中 · 不直接给答案 · 评分 1/10 后进入纠错轮
Loop · 学习闭环

从「保存知识」到「持续学习」

练习结果、错题和复习安排连成一个环：每一次作答都会改变下一次练习出什么题。

1
原始知识 · Obsidian

正式知识资产只存这里，create-only 写入，frontmatter 原样保留。

2
关联 · KarpathyWiki

LLM 把原文编译成概念/实体网络，可重建、可追溯，派生页不混入原始库。

3
检索 · 已有依据

新问题先在自己积累的知识里找证据和引用，而不是重新搜索互联网。

4
练习 · 每日一练

抽题、作答、评分、追问；SQLite 记录掌握度，复习排期反哺下一次选题。

⚠ 诚实声明：这个项目还没做到理想中的完整状态——检索质量仍在持续测试和完善，闭环正在逐步连接。但方向很明确：把学习过程真正连起来，而不只是多存一些笔记。
Architecture · 严格分层

三类资产，各归各位

系统严格区分正式知识、派生编译资产与过程性学习数据，坚持最小必要复杂度——确保知识库不被过程数据污染。

Authoritative

Obsidian Vault

权威知识底座。Sources/ 存摄入原文（带 source_uri / content_hash 元数据），Inbox/ 归你自己。

用户资产 · 只 create
Derived

KarpathyWiki

派生编译层。wiki/concepts · entities · sources 由 LLM 自动构建，可整目录重建，不视为原始知识。

插件生成 · 可重建
Process

SQLite

学习状态独立管理：题目、作答（只追加）、评分、掌握度、复习调度——绝不写入 Vault 笔记。

过程数据 · 不入库
安全边界：DSH 写入永远不碰人工维护的内容；对正式 Vault 的每次写入都经过「范围确认 + 写入计划确认」双门禁；API key 只存服务端，不进入浏览器；密钥与运行状态（.env / .state/）均不入库。

Get Started · 快速开始

把它接到你的 Obsidian 上

插件形态运行在 DSH（DeepSeek Harness）中，web 或源码方式启动均可。

准备依赖

Obsidian 打开正式 Vault，启用 obsidian-local-rest-api 与 karpathywiki 插件；Node.js ≥ 22.6。

安装插件

dsh plugin --profile web add file:…/dsh-learn-everything-0.1.0.tgz，或源码符号链接开发部署。

配置连接

DSH → 插件页填 apiKey / baseUrl / vaultName，保存前自动测试连接，错 key 不保存。

开跑

输入 /obs-remember-knowledge 摄入第一篇资料，次日 /obs-daily-practice 开始练习。
