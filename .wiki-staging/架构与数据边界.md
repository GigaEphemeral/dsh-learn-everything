# 架构与数据边界

## 三类资产，严格分层

| 层 | 载体 | 目录/位置 | 归属 | 性质 |
|---|---|---|---|---|
| 正式知识资产 | Obsidian Vault | `Sources/`（摄入原文）、`Inbox/`（待处理，归用户） | DSH 写入 `Sources/`、用户阅读 | **权威**：只 create、绝不覆盖 |
| 派生编译资产 | KarpathyWiki | `wiki/concepts` `wiki/entities` `wiki/sources` + `index.md` `log.md` `schema/config.md` | 插件自动生成 | **可重建**：不得视为原始知识 |
| 过程性学习数据 | SQLite | `.state/learning.db`（可被 `OBSIDIAN_LEARNING_DB` 覆盖；表：questions / attempts / ratings / mastery_history / review_schedule / concepts） | 插件独占 | **绝不写入 Vault 笔记** |

坚持最小必要复杂度，确保知识库不被过程数据污染。

## 安全边界

- DSH 写入永远不碰人工维护的内容：所有对正式 Vault 的写入都经过**两段确认门禁**（范围确认 + 写入计划确认），只 create
- 摄入原文带完整溯源 frontmatter：`source_uri` / `source_id` / `content_hash` / `fetched_at`；写入后**读回校验**
- wiki 派生页带 `source_file`，可回溯到摄入原文
- 注册表 `.state/sources.json`（默认为包根目录下 `.state/`，`OBSIDIAN_STATE_DIR` 可覆盖）记录 hash → vault 路径，供查重与审计；写入用临时文件 + rename，读取失败不会误判为"空注册表"
- API key 只存服务端，不进入浏览器（面板数据经围栏路由代理 Obsidian REST）
- 密钥（`.env`）与运行状态（`.state/`）均 gitignored，不入库

## Vault 目录结构

```
Vault/
├── Sources/        # 摄入原文存放处：<slug>.md（frontmatter + 原文正文）—— DSH 写入、用户阅读
├── Inbox/          # 待处理材料 —— 用户
└── wiki/           # karpathywiki 派生知识网 —— 插件自动生成，可重建
    ├── concepts/   #   概念页
    ├── entities/   #   实体页
    └── sources/    #   来源页（source_file 指回 Sources/）
```

> 说明：REST API 只列出非空目录；空文件夹（Inbox）在磁盘存在但不出现在 `/vault/` 列表。

## 源码结构（按领域分包）

```
src/
├── obsidian/     # Vault 访问层：client（HTTPS+超时）、adapter（list/read/create/append/frontmatter/search）、
│                 #   vault-path（路径校验）、mcp-client（MCP JSON-RPC）
├── wiki/         # karpathywiki 驱动：open+ingest、快照 diff、阻塞等待（超时/轮询/settle 可配）
├── ingest/       # 摄入：source-fetch、preflight（查重）、planner、pipeline（两段确认+只 create）、registry、task-state
├── search/       # 检索：intent 分类、wiki-first retriever（停用词剥离、分词回退、元数据文件过滤）
└── learning/     # 学习：question-store、attempt-store（只追加）、review-scheduler（间隔递增+加权优先级）
scripts/          # ingest-cli / search-cli / practice-db
tests/            # node --test 单测（372 个）
```

## 复习调度算法

每日练习选题按加权优先级排序（权重可配，见 [[配置参考]]）：

| 因子 | 含义 | 默认权重 |
|---|---|---|
| Overdue | 复习已逾期 | 1.0 |
| Weakness | 近期薄弱度（参考近期作答数，默认 3） | 0.8 |
| Coverage | 概念覆盖度 | 0.5 |
| Novelty | 新颖度 | 0.3 |

间隔策略：答对后 `interval_days ×= 2`（下限 1 天、上限 30 天），答错重置为 1 天且连击归零；到期优先。

## 本地构建 / 打包 / 部署

```bash
npm ci --ignore-scripts          # 安装依赖
npm run build                    # tsc：src/db + src/learning -> lib/
npm run build:client             # esbuild：右侧栏面板 bundle -> lib/client.js
npm test                         # 372 个测试（Linux CI 全绿；Windows 本地有 5 个 POSIX 路径断言失败）

npm pack                         # prepack 自动执行 build + build:client，产出 <name>-<version>.tgz
dsh plugin --profile test add file:/<abs_path>/dsh-learn-everything-<version>.tgz   # 完整包安装
dsh plugin --profile web remove dsh-learn-everything                            # 卸载
```

开发期可用源码符号链接（改源码后只需重启 DSH）：

```bash
rm -rf ~/.dsh/profiles/test/node_modules/dsh-learn-everything
ln -s /path/to/code ~/.dsh/profiles/test/node_modules/dsh-learn-everything
```

> 注意：pnpm 可能重建副本覆盖符号链接，需重做 `ln -s`。
